# Установка и обслуживание терминала

## Подготовка

Проверяемая конфигурация для установки: Windows с PowerShell 5.1, Node.js 22.12+, PostgreSQL 17, современный Chrome/Edge и принтер с драйвером Windows. Сервер и интерфейс проверены автоматически на Linux/PostgreSQL 17; установщик и вывод на физический Windows-принтер требуют проверки на терминале заказчика.

1. Установите [Node.js](https://nodejs.org/en/download) и [PostgreSQL для Windows](https://www.postgresql.org/download/windows/). Включите запуск службы PostgreSQL автоматически. Сохраните пароль пользователя базы.
2. Подключите USB-принтер. Установите драйвер производителя, выберите бумагу 58 или 80 мм в его настройках и распечатайте тестовую страницу Windows. Приложение использует очередь печати Windows; неизвестные RAW/ESC-POS-команды не отправляются.
3. Распакуйте проект в постоянную папку, например `C:\CafePOS`. Не перемещайте её после настройки автозапуска.
4. Запустите `Install-Cafe.cmd`. Введите сервер базы, порт, имя базы, пользователя и пароль. Для локальной установки подходят предлагаемые значения; пароль — тот, который задали при установке PostgreSQL. Пользователь базы должен иметь право создать базу, либо база должна уже существовать и принадлежать ему.
5. Установщик создаёт `.env` со случайным ключом сессий, выполняет `npm ci`, сборку интерфейса и миграции. Не отправляйте `.env` в GitHub или сообщения: в нём пароль базы.
6. Запустите `Start-Cafe.cmd`, создайте администратора на `http://localhost:3000`. Первого администратора можно создать только с самого терминала через localhost. Администратор добавляет сотрудников через интерфейс.

Повторный `Start-Cafe.cmd` использует уже работающий сервер. Закрытие окна браузера не останавливает его. Для остановки перед обновлением есть `Stop-Cafe.cmd` — он останавливает только записанный процесс этого приложения. Если сервер запущен вручную командой `npm start`, остановите его через `Ctrl+C` в соответствующем окне.

## Телефоны по Wi-Fi

- Используйте отдельную служебную сеть для терминала и персонала. В гостевой сети может быть включена изоляция клиентов: тогда телефоны не увидят терминал.
- Закрепите IP терминала в DHCP-настройках роутера, чтобы адрес не менялся после перезагрузки.
- В Windows назначьте этой доверенной сети профиль **Частная**. В PowerShell от администратора разрешите входящие запросы только из локальной подсети:

```powershell
New-NetFirewallRule -DisplayName 'Cafe POS LAN' -Direction Inbound -Action Allow -Protocol TCP -LocalPort 3000 -Profile Private -RemoteAddress LocalSubnet
```

- Откройте **Настройки → Сеть** и выберите адрес нужного сетевого адаптера. На телефоне в Chrome введите, например, `http://192.168.1.20:3000`. Добавьте страницу на главный экран при желании.
- Не открывайте порт 5432 для телефонов, не включайте переадресацию порта 3000 в интернет. Эта установка использует HTTP внутри доверенной сети; для удалённого доступа нужна отдельная настройка HTTPS/VPN. При переходе на HTTPS задайте `COOKIE_SECURE=true`.
- Отключите сон терминала при питании от сети. Если сервер недоступен, телефоны не сохраняют заказы локально. После ошибки связи откройте заказ и проверьте, сохранилась ли операция, прежде чем повторять её.

Если в `.env` выбран другой `PORT`, замените 3000 в адресах и правиле брандмауэра. Для стандартной установки дополнительные CORS-настройки не нужны: интерфейс и API обслуживает один сервер.

## Первое заполнение

1. **Настройки → Кафе:** название, адрес, телефон для квитанции.
2. **Сотрудники:** отдельный логин каждому; официантам роль «Официант». Не используйте один администраторский логин на всех телефонах.
3. **Меню и зал:** категории, блюда и цены; включите популярные блюда в быстрое меню. Добавьте реальные столы. Выключенный товар пропадает из кассы, но остаётся в истории.
4. **Смены:** внесите остаток разменных наличных и откройте смену. После этого можно создавать заказы.
5. Проведите приёмку по [ACCEPTANCE.md](ACCEPTANCE.md) на тестовой базе до начала реальных продаж.

## Печать

В **Настройки → Печать** доступны два режима:

- **Через браузер:** после полной оплаты открывается квитанция. Нажмите «Печатать», выберите установленный принтер, корректный формат бумаги, отключите колонтитулы браузера. Это ручная печать с кассы.
- **Автоматически через Windows:** выберите точное имя установленного принтера и ширину бумаги. Сервер поставит квитанцию в очередь после полной оплаты или возврата. Телефону не нужен доступ к USB.

Статус «Передано Windows» означает принятие задания системой печати, а не подтверждение, что бумага вышла. При отключении принтера, замятии или перезапуске сервера сначала проверьте сам принтер и очередь Windows. Затем используйте подтверждённый повтор в списке заданий. Автоматического бесконечного повтора нет, чтобы избежать дубликатов. При смене режима старые задания ручной печати не отправляются автоматически.

Проверьте на конкретном драйвере кириллицу, перенос длинных названий, поля, ширину и обрезку. Драйвер может переопределить размер бумаги. Поддержка денежного ящика и отдельных кухонных принтеров не добавлена. Техническая основа адаптера — [Windows PrintDocument](https://learn.microsoft.com/en-us/dotnet/api/system.drawing.printing.printdocument).

Квитанция приложения не является фискальным чеком. Реквизиты кассы и фискальные идентификаторы нельзя подставить вручную, чтобы имитировать ответ ККМ. Требуется настоящая интеграция с выбранным провайдером.

## Автозапуск

Из PowerShell в папке проекта:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/Enable-Autostart.ps1
```

Создаётся ярлык `Cafe POS.lnk` в папке автозагрузки текущего пользователя. Приложение запускается **после входа этого пользователя в Windows**, а не как системная служба до входа. PostgreSQL должна запускаться своей службой. Для отключения удалите ярлык из папки, открываемой командой `shell:startup`. После перезагрузки проверьте запуск и доступ с телефона.

## Резервная копия и восстановление

В `.env` при необходимости укажите пути (прямые слеши упрощают запись):

```dotenv
PG_DUMP_PATH=C:/Program Files/PostgreSQL/17/bin/pg_dump.exe
BACKUP_DIR=D:/CafeBackups
```

Запустите `Backup-Cafe.cmd`. Архив появляется только после успешного завершения `pg_dump`; незавершённый файл удаляется. Используется [custom-формат PostgreSQL](https://www.postgresql.org/docs/17/app-pgdump.html), который поддерживает восстановление через `pg_restore`.

Для ежедневных копий создайте задачу в Планировщике заданий Windows: программа — полный путь к `node.exe`, аргументы — `scripts/backup.js`, рабочая папка — `C:\CafePOS`, время — после закрытия кафе. Запускайте от пользователя, который имеет доступ к `.env` и каталогу копий. Проверяйте код завершения задачи и наличие новых архивов. Скрипт не удаляет старые копии: настройте хранение, например, последних 30 ежедневных и 12 ежемесячных архивов, и копирование на отдельное устройство. Храните `.env` отдельно в защищённой копии.

Проверка восстановления в **новую отдельную базу**, PowerShell; замените имя архива и пользователя:

```powershell
& 'C:\Program Files\PostgreSQL\17\bin\createdb.exe' -h localhost -U postgres cafe_restore_check
& 'C:\Program Files\PostgreSQL\17\bin\pg_restore.exe' -h localhost -U postgres -d cafe_restore_check --no-owner --exit-on-error 'D:\CafeBackups\cafe-2026-09-25T12-00-00-000Z.dump'
```

Не восстанавливайте поверх работающей кассы. Для проверки запустите отдельную копию проекта с `DATABASE_URL`, указывающим на `cafe_restore_check`, другим `PORT` и режимом ручной печати; убедитесь, что есть сотрудники, столы, заказы и суммы. При реальной аварии сначала сохраните доступный текущий архив, остановите сервер, согласуйте выбранную дату восстановления с владельцем, затем переключайте базу. Данные после времени копии в ней отсутствуют.

## Обновление

1. Закройте смену, остановите ввод заказов. Выполните резервное копирование.
2. Запустите `Stop-Cafe.cmd`; закройте окна на телефонах.
3. Получите новую версию репозитория, сохранив `.env` и копии. Выполните `Install-Cafe.cmd` либо `npm ci`, `npm run build`, `npm run db:init`.
4. Запустите `Start-Cafe.cmd`, обновите страницы, проверьте вход, историю, меню и печать. Миграции автоматически применяются также при `npm start`.

## Если не запускается

- `logs/server-error.log` — ошибки сервера, `logs/server.log` — запуск. Они создаются `Start-Cafe.cmd` и перезаписываются при следующем старте.
- «Сначала выполните npm run build» — повторите сборку; каталог `dist` не хранится в GitHub.
- Ошибка подключения к базе — служба PostgreSQL, реквизиты и порт в `.env`.
- Телефон не открывает страницу — IP, одна сеть, профиль Windows, правило брандмауэра, отключённая изоляция Wi-Fi.
- Печать зависла — бумага, USB, драйвер, очередь Windows; перед повтором убедитесь, что квитанция уже не была напечатана.
- Пользователь забыл пароль — администратор задаёт новый в «Сотрудники». Автоматического восстановления через email нет.
